------------------------------------------------------------------------
  1A. LOGIN
  Screen   : LoginScreen
  Trigger  : Driver/Admin taps "Login" button
------------------------------------------------------------------------

  REQUEST:
    POST /api/auth/login
    Content-Type: application/json

    Body:
    {
      "username": "rajesh@example.com",
      "password": "securepassword"
    }

  NOTE: "username" field contains the EMAIL ADDRESS (lowercased by frontend)

  RESPONSE - Success:
    {
      "success": true,
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "user": {
        "id": 1001,
        "name": "Rajesh Kumar",
        "email": "rajesh@example.com",
        "phone": "9876543210",
        "role": "Driver"
      }
    }

  RESPONSE - Failure:
    {
      "success": false,
      "message": "Invalid credentials"
    }

  WHAT FRONTEND DOES AFTER LOGIN:
    1. Saves token   --> AsyncStorage key "authToken"
    2. Saves email   --> AsyncStorage key "loggedInEmail"
    3. Calls GET /api/drivers/email/{email}  (see Section 1B)
    4. Routes based on kyc field:
       - "verified"  --> Navigate to Driver Dashboard
       - "pending"   --> Navigate to Approval Pending
       - "rejected"  --> Navigate to Driver Registration (re-submit flow)

    Selfie / Profile Photo --> "profile"

    Driving License        --> "license"
    Vehicle RC             --> "rc"

  CRITICAL: Must return a FULL https:// URL. NOT a relative path.
  Frontend reads: data.url || data.fileUrl
  Timeout: 10 seconds (frontend aborts after 10s)

  REGISTRATION FORM -- 6 STEPS BREAKDOWN
------------------------------------------------------------------------

  Step 1 - Personal:
    profilePhoto (selfie), fullName, mobile (10-digit),
    email, password (min 6 chars), dob (DD/MM/YYYY), gender

  Step 2 - Address:
    addressLine1, city, state, pincode (6-digit)

  Step 3 - Vehicle:
    vehicleType, vehicleNumber, rcNumber

  Step 4 - Documents:
    aadhaarNumber (12-digit), licenseNumber,

  Step 5 - Bank Details:
    bankName, accountHolderName, accountNumber,

  Step 6 - Review:
    Shows full summary --> triggers signup (1C) + driver creation (2B)

  VEHICLE TYPE ENUM:

------------------------------------------------------------------------
  3B. FETCH ORDER HISTORY (for earnings & trip count)
  Screen   : DriverDashboardScreen
  Trigger  : On load AND after each delivery completion
------------------------------------------------------------------------

  REQUEST:
    GET /api/drivers/{email}/orders/history
    Example: GET /api/drivers/rajesh%40example.com/orders/history

  RESPONSE Option 1 (plain array):
    [
      {
        "id": 501,
        "status": "completed",
        "amount": 185,
        "createdAt": "2026-07-28T08:30:00Z",
        "pickup": "Koramangala, 5th Block",
        "drop": "BTM Layout, 2nd Stage",
        "distance": "5.2"
      }
    ]

  RESPONSE Option 2 (object with value key):
    {
      "value": [ ...same array... ],
      "Count": 2
    }

  NOTE: Frontend handles BOTH formats:
        const orders = Array.isArray(data) ? data : (data.value || [])

  DASHBOARD COMPUTES:
    - Today's Earnings  = sum of amount for completed orders from today
    - Completed count   = total completed orders count
    - Wallet Balance    = sum of ALL completed orders' amount

------------------------------------------------------------------------
  3C. POLL FOR ACTIVE ORDERS (Real-time assignment)
  Screen   : DriverDashboardScreen
  Trigger  : Every 5 SECONDS while driver isOnline = true
  !! CRITICAL: This is called every 5 seconds -- MUST BE FAST !!
------------------------------------------------------------------------

  REQUEST:
    GET /api/drivers/{email}/orders/active

  RESPONSE -- Order assigned:
    {
      "id": 601,
      "status": "assigned",
      "pickup": "Koramangala, 5th Block, Bangalore",
      "drop": "BTM Layout, 2nd Stage, Bangalore",
      "amount": 245,
      "distance": "4.8",
      "customerName": "Priya Sharma",
      "customerPhone": "9123456789",
      "createdAt": "2026-07-28T14:00:00Z"
    }

  RESPONSE -- No active order:
    {}

  IMPORTANT: Return empty object {} NOT 404 or null when no order exists.

  FRONTEND STATE MACHINE:
    "idle"
       --> poll returns status: "assigned"
           --> Shows INCOMING ORDER modal (30 second countdown)
               |-- Driver ACCEPTS --> PUT /api/orders/{id}/status { "accepted" }
               |       --> Active Delivery:
               |       --> Step 1 tap --> PUT status { "picked_up" }
               |       --> Step 2 tap --> PUT status { "transit" }
               |       --> Step 4 tap --> PUT status { "completed" }
               |       --> deliveryState = "idle"
               --> Driver REJECTS (or 30s expires)
                       --> PUT /api/orders/{id}/status { "searching" }
                       --> deliveryState = "idle"

------------------------------------------------------------------------
  3D. UPDATE ORDER STATUS
  Screen   : DriverDashboardScreen
  Trigger  : On each delivery step button tap
------------------------------------------------------------------------

  REQUEST:
    PUT /api/orders/{orderId}/status
    Content-Type: application/json

    Body: { "status": "accepted" }

  STATUS PROGRESSION:
    Driver Event                   --> Status to Send
    --------------------------------------------------
    Driver accepts order           --> "accepted"
    Driver rejects order           --> "searching"
    Step 1: Reached Pickup         --> "picked_up"
    Step 2: Package Loaded         --> "transit"
    Step 4: Delivery Complete      --> "completed"

  RESPONSE: Any 2xx HTTP status (body not read by frontend)

------------------------------------------------------------------------
  3E. TOGGLE DRIVER ONLINE / OFFLINE
  Screen   : DriverDashboardScreen
  Trigger  : Driver flips the Online toggle switch
------------------------------------------------------------------------

  REQUEST:
    PUT /api/drivers/email/{email}/status
    Content-Type: application/json

    Body (Go Online):  { "status": "online" }
    Body (Go Offline): { "status": "offline" }

  RESPONSE: Any 2xx HTTP status

================================================================================
  SECTION 13 -- CRITICAL RULES
================================================================================

  RULE 1: KYC VALUES ARE CASE-SENSITIVE
    Must be exactly: "verified" | "pending" | "rejected"
    NOT: "Verified", "VERIFIED", "Approved", "approved"
    Login routing DEPENDS on this exact value.

  RULE 2: IMAGE URLS MUST BE FULL HTTPS:// URLS
    Frontend DISCARDS any URI not starting with "http://" or "https://"
    WRONG:  "/uploads/image.jpg"
    CORRECT: "https://poteranusha.s3.ap-south-2.amazonaws.com/..."

  RULE 3: RATING FIELD IS A STRING
    Return: "4.8"  (NOT the number 4.8)

  RULE 4: ORDER HISTORY ACCEPTS BOTH RESPONSE FORMATS
    Frontend handles: plain array [ ] OR object { "value": [ ], "Count": N }

  RULE 5: /orders/active MUST RETURN {} WHEN NO ORDER
    Do NOT return 404 or null.
    Return empty JSON object {} when no active order exists.
    This endpoint is called every 5 seconds -- must be FAST.

  RULE 6: S3 REGIONAL URL
    Correct:  poteranusha.s3.ap-south-2.amazonaws.com
    Wrong:    poteranusha.s3.amazonaws.com

  RULE 7: DRIVER EMAIL AS IDENTIFIER
    Many endpoints use email as URL path param, not numeric ID.
    Both lookup methods (email AND numeric ID) must be supported.

  RULE 8: IMAGE UPLOAD TIMEOUT
    Frontend aborts uploads after 10 seconds.
    Ensure /api/upload/image responds within 10s.

================================================================================
  SECTION 14 -- COMPLETE END-TO-END JOURNEY
================================================================================

  -- NEW DRIVER REGISTRATION --

  1. App opens --> Splash (3s) --> Role Select --> Driver
  2. Login Screen --> tap Register
  3. Step 1 (Personal):
       Selfie --> POST /api/upload/image { category: "profile" }
       Fill: name, mobile, email, password, DOB, gender
  4. Step 2 (Address):
       Fill: addressLine1, city, state, pincode
  5. Step 3 (Vehicle):
       Select vehicleType, enter vehicleNumber, rcNumber
  6. Step 4 (Documents):
       Aadhaar upload --> POST /api/upload/image { category: "aadhaar" }
       License upload --> POST /api/upload/image { category: "license" }
       RC upload      --> POST /api/upload/image { category: "rc" }
       Fill: aadhaarNumber, licenseNumber
  7. Step 5 (Bank):
       Passbook upload --> POST /api/upload/image { category: "bankpassbook" }
       Fill: bankName, accountNumber, ifscCode, accountHolderName
  8. Step 6 (Review):
       Driver reviews, taps Submit
       Verification animation (7.2 seconds)
       --> POST /api/auth/signup   (create login account)
       --> POST /api/drivers       (create driver profile)
  9. Navigate to Approval Pending Screen

  -- ADMIN KYC APPROVAL --

  10. Admin logs in (role: admin)
  11. GET /api/admin/metrics              --> see pending count
  12. GET /api/admin/drivers?status=pending  --> list pending drivers
  13. Admin reviews:
      Approve: PUT /api/admin/drivers/{id}/kyc { "status": "verified" }
      Reject:  PUT /api/admin/drivers/{id}/kyc { "status": "rejected", "reason": "..." }

  -- VERIFIED DRIVER DAILY OPERATIONS --

  14. Driver logs in:
      POST /api/auth/login
      GET /api/drivers/email/{email} --> kyc: "verified" --> Dashboard
  15. Dashboard loads:
      GET /api/drivers/email/{email}          --> name, rating, tenure
      GET /api/drivers/{email}/orders/history --> earnings, trips
  16. Driver goes Online:
      PUT /api/drivers/email/{email}/status { "status": "online" }
  17. Frontend polls every 5 seconds:
      GET /api/drivers/{email}/orders/active
  18. Backend assigns order --> response: { "status": "assigned", ... }
  19. Incoming Order modal shown (30s countdown)
  20. Driver taps Accept:
      PUT /api/orders/{id}/status { "status": "accepted" }
  21. Step 1 (Reached Pickup):
      PUT /api/orders/{id}/status { "status": "picked_up" }
  22. Step 2 (Package Loaded):
      PUT /api/orders/{id}/status { "status": "transit" }
  23. Step 3 (Start Delivery -- no status update, UI only)
  24. Step 4 (Delivered, OTP collected):
      PUT /api/orders/{id}/status { "status": "completed" }
  25. Dashboard refreshes:
      GET /api/drivers/{email}/orders/history --> updated earnings
  26. Back to idle, continues polling

  -- EARNINGS & SETTLEMENT --

  27. Driver opens Earnings tab:
      GET /api/drivers/{email}/orders/history
      Frontend calculates today/weekly/monthly/total breakdowns

  28. Driver opens Settlement History:
      GET /api/drivers/{email}/orders/history
      Filters to completed orders, shows as "Settled" records
